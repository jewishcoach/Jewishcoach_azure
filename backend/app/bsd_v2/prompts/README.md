# מפת ההוראות למאמן (V3)

כל ההוראות למאמן נמצאות בתיקייה הזו. בכל תור המערכת מרכיבה את ההוראות מכמה שכבות
(הקוד: `prompt_manager.py`, הפונקציה `assemble_system_prompt`).

## 1. הוראות כלליות — בכל תור, בכל שלב (`core/`)

| קובץ | מה יש בו |
|---|---|
| `persona.md` | מי המאמן, סגנון, חום, "המילים שלו", מגדר, ביטויים שאסור להשתמש בהם |
| `coach_charter.md` | כללי עבודה: בידוד שלב, מה אסור (ניתוח, עצות, האכלה בכפית) |
| `process_map.md` | מפת התהליך והקומות |
| `response_format.md` | איך המאמן מחזיר תשובה ומה הוא מעדכן |
| `v3_hybrid_addon.md` | כללי הממשק עם הכרטיסים: שיקוף פעם אחת, לא לחשוף את המנגנון |

"תוספת V3" נטענת **לפני** קובץ הבסיס ומגדירה מה לדלג עליו בו. בשלבים 2, 10, 12, 13, 14 ו-15 נטענת התוספת בלבד
(`_V3_OVERLAY_ONLY_STEPS` ב-`prompt_manager.py`), כי קבצי הבסיס שלהם סותרים את המבנה החדש.

**לא בשימוש:** שאר הקבצים בתיקייה `stages/v3/` (כמו `v3/s2_event.md`, `v3/s9_paradigm_stance.md`) — שאריות
מגרסה קודמת. עריכה שלהם לא משפיעה על המאמן.

## 3. מה נמצא בקוד ולא בקבצים

- **תנאי מעבר בין שלבים** (`STAGE_GATES_HE`) ו**איזה נתון לאסוף בכל שלב** (`STAGE_COLLECTED_DATA_HE`) —
  ב-`prompt_manager.py`. ההחלטה בפועל מתי לעבור שלב — `_check_gate_met_v3` ב-`single_agent_coach.py`.
- **תיקונים אוטומטיים אחרי שהמאמן כתב:**
  - `single_agent_coach.py` — `_fix_addressee` (גוף ראשון → שני, "בואי" לאישה), `_build_v3_paradigm_hint`
    (פרדיגמה שנראית כמו דפוס).
  - `api/chat_v2.py` — `drop_repeated_trigger_reflection` (הטריגר פעמיים בשלב 10).
  - `routers/tools.py` — משפט המעבר הקבוע אחרי אישור המצוי, הסרת המשפט שמפרט את הבדיקות בשלב 2, הרכבת
    הבקשה לאימון (`compose_coaching_request`).
- **בדיקת בטיחות** — `bsd_v2/safety_check.py`.
- **הכרטיסים** (מה שהמשתמש רואה וממלא) — `frontend/src/v3/components/tools/`.

## 4. לקח חשוב לעריכה

המודל באתר (gpt-4.1-mini) **מעתיק דוגמאות כמעט מילה במילה** — דוגמה או תבנית בקובץ משפיעה יותר מהוראה כתובה.
כשמשנים התנהגות, בודקים ומעדכנים גם את הדוגמאות ואת הכותרות, לא רק את ההוראות.
